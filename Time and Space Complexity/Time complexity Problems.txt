Time complexity Problems


Problem TC-1: Linear Search Time Complexity
-------------------------------------------
Sample Input Array: {8, 61, 2, 3, 4, 0}  (n = 6)

1. Best Case (target = 8)
   - Definition: The best case occurs when the target element is found at the first position.
   - Explanation: With target 8 at index 0, the algorithm performs 1 comparison and terminates immediately.
   - Time Complexity: O(1)  (constant time)

2. Worst Case (target = 0 or target = 5, not present)
   - Definition: The worst case occurs when the target is at the last position or not present in the array.
   - Explanation: 
        * For target 0 (last index): 6 comparisons are made.
        * For target 5 (absent): 6 comparisons are made before concluding "not found".
   - Time Complexity: O(n)  (linear time)

3. Average Case (target at a random position)
   - Definition: Assuming the target is equally likely to be at any of the n positions (and present).
   - Derivation: Expected comparisons = (1 + 2 + ... + n) / n = (n + 1) / 2
   - Time Complexity: O(n)  (linear time; constants dropped in Big-O)


Problem TC-2: Iterative Binary Search Complexity
-------------------------------------------------
Sample Sorted Array: {0, 2, 3, 4, 8, 61}  (n = 6)

1. Step-by-step search for target = 4 (0-based indexing)

   Initial: low = 0, high = 5
      mid = floor((0 + 5) / 2) = 2  -> arr[2] = 3
      3 < 4  -> search right half: low = mid + 1 = 3

   Step 2: low = 3, high = 5
      mid = floor((3 + 5) / 2) = 4  -> arr[4] = 8
      8 > 4  -> search left half: high = mid - 1 = 3

   Step 3: low = 3, high = 3
      mid = floor((3 + 3) / 2) = 3  -> arr[3] = 4
      Found target at index 3.

   Total comparisons: 3

2. Worst-case number of comparisons and Big-O

   Each iteration halves the search space. Starting with n elements, after k iterations:
      remaining size ≈ n / (2^k)

   Process stops when 1 element remains:
      n / (2^k) ≤ 1  =>  2^k ≥ n  =>  k ≥ log₂(n)

   Maximum comparisons ≈ log₂(n) + constant

   Worst-case Time Complexity: O(log n)


Problem TC-3: Merge Sort Time Complexity
-----------------------------------------
Sample Input Array: {8, 61, 2, 3, 4, 0}  (n = 6)

1. Division/split tree (recursive splitting until size 1)

   Level 0:              [8, 61, 2, 3, 4, 0]
                        /                    Level 1:      [8, 61, 2]           [3, 4, 0]
                 /    \               /       Level 2:   [8]  [61, 2]         [3]   [4, 0]
                   /  \                  /      Level 3:     [61]  [2]             [4]   [0]

   Each leaf is a single-element subarray (already sorted).

2. Recurrence relation and recursion-tree solution

   Recurrence:
      T(n) = 2T(n/2) + cn

      where:
        - 2T(n/2): two recursive calls on halves
        - cn: linear-time merge of two sorted halves

   Recursion tree by levels:

      Level 0: 1 problem of size n        -> cost = cn
      Level 1: 2 problems of size n/2     -> cost = 2 * c(n/2) = cn
      Level 2: 4 problems of size n/4     -> cost = 4 * c(n/4) = cn
      ...
      Level k: 2^k problems of size n/(2^k) -> cost = 2^k * c(n/(2^k)) = cn

   Tree height h when subproblem size = 1:
      n / (2^h) = 1  =>  h = log₂(n)

   Number of levels: log₂(n) + 1  (from 0 to log₂(n))

   Total work:
      T(n) = cn * (log₂(n) + 1) = O(n log n)

   Final Time Complexity: O(n log n)
